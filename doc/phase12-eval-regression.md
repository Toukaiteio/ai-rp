# Phase 12：评测集和自动回归

前十一阶段每加一个功能，验证方式都是「跑一遍看看」。Phase 12 把这件事变成**可重复的**：
50 组固定输入、三族指标、一条能和基线比对的命令。

- 评测集：`lib/eval/cases.ts`（50 组，15 类）
- 连贯性序列：`lib/eval/sequences.ts`（5 条 × 4 轮）
- 指标：`lib/eval/metrics.ts`（三族 13 项）
- 跑批：`scripts/eval.ts`，`pnpm test:roleplay` / `pnpm test:roleplay:live`
- 测试：`lib/eval/metrics.test.ts`（44 条）
- 基线：`doc/phase12-eval.json`（离线装配）、`doc/phase12-eval-live.json`（真机指标）

---

## 12.1 最小评测集

50 组，覆盖 12.1 列出的全部输入类型：

| 类别 | 组数 | 盯什么 |
| --- | --- | --- |
| 普通闲聊 | 3 | 别把简单问题答复杂 |
| 模糊输入 | 3 | 不反问玩家 |
| 情绪冲突 | 3 | 人设不崩、不一跳到底 |
| 场景切换 | 4 | 地点变了要有交代 |
| 多角色 | 3 | who 写清楚、不借他人之口交代 |
| 长文本 | 3 | 不被玩家带跑 |
| 玩家拒绝 | 3 | 不替玩家改主意 |
| 玩家沉默 | 3 | 沉默也是一个回合 |
| 追问伏笔 | 3 | 追问不能问出答案 |
| 角色不愿回答 | 4 | 避讳要守住 |
| 角色说话风格 | 4 | 句长和调子稳定 |
| 中英切换 | 4 | 语言跟着玩家走 |
| 附件输入 | 3 | 只说附件上真有的 |
| 工具调用 | 3 | 工具不走正文 |
| 重新生成 | 4 | 纠偏生效、旧版不泄漏 |

12.1 列的是 15 项。「重新生成」是**动作**而不是输入类型，但它需要自己的用例
（被弃用的上一版 + 纠偏指令），所以单列一类；其余 14 项是输入类型。
两类加起来覆盖全部要求。

每组都标了 `checks`——这一组该盯哪几项指标。改坏了能直接指到类别。

## 12.2 自动检查

```bash
pnpm test           # 单元测试
pnpm build          # 构建
pnpm lint           # 静态检查
pnpm test:roleplay  # 评测集（离线装配检查，几秒，不花钱）
```

真机版（要 Key，跑约 10 分钟）：

```bash
$env:YOSEI_API_KEY = "sk-..."
pnpm test:roleplay:live
```

两条路的产出不一样，这是有意的：

| | 离线 `test:roleplay` | 真机 `test:roleplay:live` |
| --- | --- | --- |
| 调模型 | 否 | 是 |
| 验什么 | 装配正确性 | 内容质量 |
| 出指标 | 不出（没有正文） | 三族 13 项 |
| 和基线比 | 否 | 是，退化就非零退出 |
| 适合 | 每次改提示词都跑 | 改完提示词、发版前 |

**离线验的七件事**（都是只有装配层才知道对不对的）：

1. 组装不报错、预算不超；
2. 同样输入两次组装，消息和前缀指纹完全一致（纯函数，缓存才靠得住）；
3. 回合层和输出契约该有的段都在；
4. 重新生成那几组，被弃用的版本**一个字都没进提示词**（Phase 11.1 的硬规则）；
5. 附件说明真的进了提示词；
6. 语言锁定跟着玩家那一句走；
7. 角色名进了提示词。

## 12.3 评测指标

三族 13 项，全部从跑批记录里算，不额外调模型。**每项都返回分子分母**，
不只给百分比——分母是 0 还是 100，对判断问题完全不同。

### 结构指标

| 指标 | 算法 |
| --- | --- |
| `validBlockRatio` | 没被降级或丢弃的块 / 总块数 |
| `invalidActRatio` | 不合格 act / act 总数 |
| `badWhoRatio` | who 写成代词或名字不准 / act + dlg 总数 |
| `toolTagLeakRatio` | 把工具调用写成标签的轮次 / 总轮次 |

### 叙事指标

| 指标 | 算法 |
| --- | --- |
| `playerControlRatio` | 替玩家行动过的轮次 / 总轮次 |
| `characterDriftRatio` | 人设违背过的轮次 / 总轮次 |
| `repeatedRatio` | 和上一轮撞车的轮次 / 总轮次 |
| `unsupportedSettingRatio` | 过度推进或现编角色名的轮次 / 总轮次 |
| `plotOverreachRatio` | 一次解决悬念的轮次 / 总轮次 |

叙事这几项都是「一轮里犯一次就算」，不按次数累加——同一轮替玩家行动三次和一次，
对读者的伤害是一样的。

### 连贯性指标

| 指标 | 算法 |
| --- | --- |
| `sceneLocationKept` | 地点没变，或者变了但正文里有 `scene` 块交代 |
| `timelineConsistent` | 时间没倒退（没变或往前推都算一致） |
| `characterStateKept` | 没有凭空往场景里塞没提过的人 |
| `threadRetention` | 上一轮开着的线这一轮没有无声消失 |

连贯性是**跨轮次**的，所以单轮用例算不出来。`lib/eval/sequences.ts` 补了 5 条
连续 4 轮的序列，每轮都走真实导演阶段（产出 `statePatch` / `threadPatch`），
把状态和剧情线一路攒下来再比。

`deepseek-v4-flash-200k`。

| 指标 | 结果 |
| --- | --- |
| 合法消息块比例 | 100%（317/317） |
| 非法 act 比例 | 0%（0/91） |
| 错误 who 比例 | 0%（0/207） |
| 工具标签泄漏比例 | 0%（0/70） |
| 替玩家行动比例 | 0%（0/70） |
| 角色设定违背比例 | 2.9%（2/70） |
| 重复句比例 | 0%（0/70） |
| 无依据新设定比例 | 0%（0/70） |
| 过度推进剧情比例 | 0%（0/70） |
| 场景位置保持率 | 86.7%（13/15） |
| 时间线一致率 | 100%（15/15） |
| 角色状态保持率 | 86.7%（13/15） |
| 未解决剧情线保留率 | 100%（12/12） |

### 跑批过程中抓到的一个测量错误

第一次真机跑批，`threadRetention` 报 **71.4%**（10/14），看起来像剧情线在漂。
去翻落盘的逐轮记录，发现 5 条序列各自的线一条都没丢——**是测量本身错了**。

原因：连贯性指标按数组顺序比相邻两轮，而数组里装着 5 条**互不相干**的序列。
seq-01 的最后一轮（酒堂、有 1 条线）和 seq-02 的第一轮（另一个会话）被算成
「场景换了没交代」+「剧情线丢了」。每条序列的边界都贡献一次假丢失。

修法是给每轮加 `run` 字段（属于哪一次会话），只比同一次会话内相邻的两轮。
修完之后 `threadRetention` 是 **100%**，`sceneLocationKept` 从 78.9% 升到 86.7%
（升的部分也全是假的丢失）。

**这个错误只有在「指标 + 逐轮记录都落盘」的情况下才查得出来。**
只报一个百分比的话，71.4% 看起来完全像个真问题，然后就会去改提示词——
去修一个不存在的毛病。

## 已知取舍

- **连贯性指标需要序列才有效。** 单轮用例那四项全是「无从判定」，
  这是对的——一轮之内没有可比的对象。要更多连贯性覆盖就加序列，
  加单轮用例不会让这四项变好。
- **退化阈值是 5%。** 真机跑批有噪声（同一份代码两次结果不完全一样），
  阈值太低会天天报警，然后大家就不看报告了。写在 `REGRESSION_TOLERANCE`。
- **「无依据新设定」是两个信号的合取。** 用「过度推进」或「who 写不准」
  近似，单独一个都不够。它抓的是明显现编，不是全部无依据设定——
  真要判准需要一份世界设定清单做比对，那是下一步。
- **时间线只判倒退。** 常见中文时间词按顺序排，认不出来就不判。
  宁可漏判也不误判：时间词写法千变万化，硬判会制造假警报。
- **真机跑批约 10 分钟、70 次调用。** 不适合每次改代码都跑，
  离线装配检查才是那个该常跑的。
