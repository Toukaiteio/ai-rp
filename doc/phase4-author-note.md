# Phase 4：Author's Note 回合强化

Phase 3 把提示词分成了稳定层和回合层，但作者注只是回合层里的一行。
Phase 4 把它单独拎出来，给它明确的职责、明确的插入位置和三层来源。

- 代码入口：`lib/prompt/note.ts`（解析、频率、深度、纠偏）
- 组装位置：`lib/prompt/index.ts` 的 `assemble`（插进历史，不是回合层）
- 界面：`components/chat/AuthorNoteSheet.tsx`（顶栏大脑图标）
- 测试：`lib/prompt/note.test.ts`（16 条）、`lib/prompt/assemble.test.ts`、`components/chat/AuthorNoteSheet.test.tsx`
- 真机对照：`doc/phase4-note-baseline.json`

---

## 1. 用途：只放「这一轮怎么写」

作者注**不放世界设定**。世界设定属于角色卡、世界书和关键事实；
在作者注里再写一遍，只会出现两处说法打架，而且它会随轮次变化，
本来就不适合承载稳定设定。

它放的是五类东西，面板里的常用句直接覆盖这五类：

| 类别 | 例子 |
| --- | --- |
| 当前回合节奏 | 本轮保持克制。 |
| 当前写作重点 | 只写角色对玩家刚才那句话的直接反应。 |
| 当前格式提醒 | act 只保留一个可见动作。 |
| 临时风格约束 | 这一轮别用比喻，白描就好。 |
| 重新生成时的纠偏 | 上一版替玩家行动了，这一轮注意。 |

**玩家主权也在这一层重复**：「不要替玩家行动」既在系统提示里，也在回合层里，
作者注里还能再强调一次。这条规则被违反的代价最高，值得说三遍。

面板里明写了边界，免得玩家把设定写进来：

> 只写这一轮怎么写：节奏、重点、格式提醒、临时风格。世界设定和人物设定请写进角色卡，不要写在这里。

## 2. 插入位置：聊天历史之后，最终用户输入之前

默认 `depth = 1`，也就是插在**最后一条玩家输入之前**：

```
… 更早的历史 …
[system] 作者注
[user]   玩家这一轮说的话
[system] 本轮状态 / 模式 / 输出要求（回合层）
```

这样比放在系统提示开头更有影响力：放在最前面，隔了几十轮历史早就被冲淡了；
放在最后一条玩家输入之前，它离生成最近，又不会盖过玩家刚说的那句话。

实现在 `assemble` 里：作者注不再进回合层，而是作为一条 system 消息插进历史数组，
并且**它的 token 从历史预算里扣**（`budget.blocks.note`），
这样它既不会把历史挤爆，也不会让总预算超出去。

包装上带一句边界说明，否则模型会把注记里的句子当成剧情事实写进正文：

```
作者注（管这一轮的节奏和写法，优先级高于上面的常规要求；不是新的设定或事件，不要照抄进正文）：
本轮保持克制。
```

## 3. 三层来源

优先级从高到低，`resolveAuthorNote` 是唯一的判定点：

| 来源 | 存哪儿 | 生命周期 |
| --- | --- | --- |
| 本轮临时注记 | 内存（`runTurn` 的参数） | 只影响这一轮 |
| 当前聊天专属 | 会话（`ChatSession.authorNote`） | 跟着这场对话 |
| 角色卡默认 | 卡（`data.author_note`） | 跟着这张卡，导出导入都在 |

两条规则值得单独说：

1. **临时注记一旦有内容就独占。** 重新生成时玩家要的是「这一轮纠正什么」，
   这时候再叠上常规注记，模型会分不清哪个是当务之急。
2. **显式关掉就不再往下找。** 会话里把注记关掉（`enabled: false`）时，
   不会被卡上的默认注记顶回来——玩家的意图优先于卡的默认值。

### 重新生成时的纠偏信息

被质量门拒收后点「重新生成」，`retryRejected` 会把拒收原因翻成一条临时注记：

```
重新生成：上一版没有通过校验，被丢弃了。
问题：替玩家说话或行动：narr 里替玩家做动作：你坐下
这一轮重写时避免同样的写法，其余内容照常推进。
```

最后一句是有意加的：只说「别这样」会让模型缩手缩脚，补一句「其余照常推进」，
它才知道纠偏不等于收着写。

## 4. 可扩展项

| 能力 | 实现 |
| --- | --- |
| **深度** | `depth`，默认 1（最后一条之前），0 是最后一条之后，上限 6（`MAX_NOTE_DEPTH`）。超出范围自动收进合法区间，不会越界。 |
| **插入频率** | `frequency`，0 = 从不，1 = 每轮，N = 每 N 轮。第 0 轮总是出现，否则开头几轮会没有作者注。 |
| **当前聊天专属** | 存在 `ChatSession.authorNote`，随会话落盘。 |
| **默认 Author's Note** | 角色卡的 `author_note` 字段，角色编辑器里可以写；导出再导入原样保留（`lib/cards/author-note.test.ts`）。 |
| **重新生成时临时 Author's Note** | `runTurn` 的第五个参数，只影响这一轮，不落盘。 |

界面上：顶栏的大脑图标打开面板，可以写正文、点常用句追加、选频率和插入位置、
清空回退到卡的默认。清空和保存都会立刻落盘到当前会话。
面板顶部还会只读列出当前场景状态（Phase 5 加的），
见 [phase5-scene-state.md](phase5-scene-state.md)。

## 5. 真机对照（2026-10-18）

同一批 26 组用例、同一个模型，只有作者注这一个变量。

| 指标 | 没有作者注（Phase 3） | 加了「克制」作者注（Phase 4） |
| --- | --- | --- |
| 质量门 | 原样落地 26 · 降级 0 · 拒收 0 | 原样落地 25 · 降级 1 · 拒收 0 |
| 符合机器预期 | 26 / 26 | 26 / 26 |
| 平均篇幅 | 122 字 | **106 字** |
| 对白段数 | 50 | 49 |
| act | 32 个，坏 0 | 28 个，坏 1 |
| 替玩家 / 复读 / 语言切错 / 人物漂移 | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |

用的注记：

> 本轮保持克制。只写角色对玩家刚才那句话的直接反应。act 只保留一个可见动作，不超过 12 个字。不要推进新的剧情线。

**结论：作者注是个有效的节奏旋钮，不是质量加分项。** 篇幅从 122 字压到 106 字，
而合格率没有下降（26/26 仍全部符合预期）。想要更长或更短，改这一条比改系统提示快得多，
也不会打掉前缀缓存。

### 这次对照顺带修掉的两个误判

跑这一轮时暴露了检查器的两个误报，都是「正常句子被当成违规」：

1. **`她继续擦那只杯子`** 被判成「act 含多个动作」——因为「继续」被列进了串联词。
   它修饰的是同一个动作，不是第二个动作。已从串联词表里去掉。
2. **`要喝热的就坐下`** 被判成「dlg 混入转述句式」——原判据允许「任意 2 到 4 个汉字」
   当主语，「要喝热」正好符合。现在主语只认代词和已知人名（由调用方传进来）。

两条都补成了回归测试。第一个作者注版本因此多报了 2 条问题，
修掉之后这一轮的真实结果是 25 合格 + 1 降级，和上表一致。

## 7. 已知取舍

- **作者注不再是「每轮都有的东西」。** 它可以按频率出现，也可以被显式关掉。
  关掉之后模型只靠回合层和系统提示，长对话里的节奏会更依赖模式推断。
- **它每轮都占历史预算。** 上限 600 字（`MAX_NOTE_CHARS`），超出截断；
  面板里写太长会挤掉历史，所以常用句都是短句。
- **深度超过 3 没有做进界面**，只在 `note.ts` 里支持到 6。
  再往前插就开始影响历史本身的连贯性，日常也用不到。
- **纠偏注记只在「拒收后重新生成」时自动生成。** 玩家自己点「重新生成」时
  不带纠偏信息——那一轮没被拒收，没有明确的「上一版错在哪」可讲。
