# Phase 6：未完成剧情线

Phase 5 让模型知道「此刻在哪儿」。Phase 6 让它知道「还欠着什么」，
而且**不要每轮把所有悬念都摆在它面前**。

- 代码入口：`lib/story/`（类型、更新规则、挑选策略，全是纯函数）
- 提取来源：导演阶段顺带输出（`lib/prompt/turn-plan.ts` 的 `threadPatch`）
- 注入位置：回合层的「还没交代完的几件事」
- 存储：会话（`ChatSession.storyThreads`）
- 测试：`lib/story/threads.test.ts`（24 条）
- 真机结果：`doc/phase5-state-check.json`（和场景状态同一次跑批），`pnpm state-check`

---

## 1. 数据结构

```ts
interface StoryThread {
  id: string;
  title: string;              // 一句话，不超过 20 字
  summary: string;            // 现在知道什么
  status: "open" | "resolved" | "dormant";
  importance: number;         // 1 到 5
  lastActiveAt: number;       // 最后一次被提到的轮次
  relatedCharacters: string[];
}
```

例：

```
title:     深月风花的绷带
summary:   她左手缠着绷带，说是烫伤却从不摘下；被问到就岔开话题
status:     open
importance: 4
relatedCharacters: [深月风花]
```

**和邻居的分工**：场景状态是「此刻」，每轮覆盖；剧情线是「悬着的事」，跨几十轮有开有合；
记忆（journal / facts）记「发生过什么」。

## 2. 更新：按标题认线，已解决的不能复活

导演顺带输出 `threadPatch`，`applyThreadPatch` 负责合并：

| 规则 | 说明 |
| --- | --- |
| 按 id 或标题认线 | 给了 id 按 id；否则先找标题完全一致的，再找互相包含的（「绷带」能认回「左手绷带的来历」）。只挡掉单字标题，否则「她」会匹配到一切 |
| 只写变了的 | 没提到的线原样保留；内容没变就不算更新，但会刷新 `lastActiveAt` |
| 新线默认 open | 导演提到它，说明它现在悬着。新线直接标 `resolved` 的不入库 |
| **已解决的不能复活** | `resolved` 的线再被提到，只刷新「最近提到」，内容一个字都不改，并记进 `blocked` |
| 上限 40 条 | 超了先丢最旧的已解决项，再丢最旧的搁置项，最后才动 open 的 |

「不能复活」这条是有意的：模型很容易在回顾时把一条早就交代完的线重新说成悬念，
一旦允许复活，玩家会看到「已经解释过的事又被当成谜」——那是最伤沉浸感的一种错。

## 3. 注入策略：不要每轮注入全部

`selectThreads` 只挑**最多三条**，四个入选理由：

| 理由 | 判定 | 权重 |
| --- | --- | --- |
| 玩家追问 | 玩家这句话里出现了线的标题、相关角色名，或与之共用一个 3 字以上的片段 | 直接入选 |
| 最近提到 | 最近 6 轮正文里出现过，**而且**这条线本身在最近 8 轮内动过 | +30 |
| 当前场景相关 | 相关角色在场，或线的摘要里提到了当前地点 | +25 |
| 高重要度 | `importance >= 4`，即使最近没提到也留一条 | +10 |

其余的一律不注入。已解决的线永远不注入；`dormant` 的只在玩家追问时注入。

中文没有空格，判断「是不是在说同一件事」只能按字比：先找 3 字片段，找不到退到 2 字片段，
并跳过「什么、怎么、这个」这类虚词——否则任何一句问话都会命中一堆剧情线。

**注入时的措辞也是策略的一部分**：

```
还没交代完的几件事（只是背景，不要为了它们硬推进，也不要在正文里提起这个列表）：
- 深月风花的绷带：她左手缠着绷带，说是烫伤却从不摘下……
```

只说「这是背景」，不说「请推进这些剧情线」。前者让模型把它当氛围，
后者会让它变成一个急着收线的写手。

## 4. 防止的问题

| 要求 | 做法 |
| --- | --- |
| 不要因为有悬念就强行推进 | 注入措辞是「只是背景，不要硬推进」；导演提示里也不要求这一轮处理它们 |
| 不要每轮提醒模型「还有几个悬念」 | 每轮最多三条，绝大多数轮次只注入 1 到 2 条；没有相关线时一条都不注入 |
| 不要把所有未解决事项都变成当前剧情 | 只有玩家追问、最近提到、场景相关、高重要度这四种才入选；`dormant` 默认不注入 |
| 已解决的剧情线不能重复复活 | `applyThreadPatch` 挡下并记进 `blocked`；`selectThreads` 永不注入 `resolved` |

## 5. 真机验证（2026-10-18）

和场景状态同一次跑批，一张卡连续 6 轮，`pnpm state-check`。

| 指标 | 结果 |
| --- | --- |
| 新登记 | 1 条（深月风花的绷带） |
| 收线 | 0 条 |
| 挡复活 | 0 次 |
| 每轮注入条数 | 0 / 1 / 1 / 1 / 1 / 1（上限 3） |
| 注入理由分布 | 最近提到 5 · 当前场景相关 5 |

三点值得记：

1. **第一轮就登记了线，之后五轮都没有重复登记。** 说明「按标题认线」是有效的，
   导演每轮都提到这条绷带，但没有变成五条重复的线。
2. **每轮只注入一条，不是全部。** 这一轮只有一条线，所以看不出上限的效果；
   但「注入 0 条」出现在第 1 轮（那时还没有线），说明空列表时不会硬凑。
3. **六轮都没有误收线。** 玩家在第 4 轮直接问「她的手是不是还没好」，
   模型也只在正文里岔开话题，没有把线标成 resolved——正是「不要因为有悬念就强行推进」
   想要的行为。

## 6. 验收对照

| Phase 6 要求 | 落地位置 |
| --- | --- |
| 数据结构 | `lib/story/types.ts` 的 `StoryThread`，字段与建议一致 |
| 记录内容（标题 / 状态 / 重要度 / 相关角色） | 同上，另加 `summary` 和 `lastActiveAt` |
| 只注入当前场景相关 / 最近被提到 / 高重要度 / 玩家追问 | `selectThreads` 的四个理由，测试逐条覆盖 |
| 不要因为有悬念就强行推进 | `formatThreads` 的措辞 + 导演提示不要求本轮处理 |
| 不要每轮提醒还有几个悬念 | 每轮最多三条；无相关线时一条都不注入 |
| 不要把未解决事项都变成当前剧情 | 四种理由之外的线不入选；`dormant` 默认不注入 |

## 7. 已知取舍

- **线的登记完全靠导演。** 它漏登记就没有线，误登记就会多一条。目前没有人工增删入口，
  界面上只能看（作者注面板顶部按重要度列出还没交代完的线）。
- **重要度由模型自评。** 1 到 5 的分档靠提示里的一句说明，没有校准。
  真机上它给绷带打了 4，算合理。
- **`summary` 会随更新被覆盖。** 这是有意的：剧情线描述的是「现在知道什么」，
  不是变更日志。想要历史，靠会话正文和摘要。
- **注入上限是三条。** 三条以上就开始像清单了。这个数字写在 `DEFAULT_THREAD_LIMIT`，
  以后要调只改一处。
- **不参与导出。** 剧情线是给模型看的当下状态，不是作品的一部分；
  EPUB 导出走的是正文和章节结构。
